# Android permissions — merged release manifest audit

Source: `build/app/intermediates/packaged_manifests/release/processReleaseManifestForPackage/AndroidManifest.xml`
(the real merger output of the release build, plugins included), re-verified
2026-10-20. Nothing is declared in `android/app/src/main/AndroidManifest.xml`
that the app does not use, and no plugin injects an unused permission.

## Every permission and why it stays

| Permission | Injected by | Justification |
|---|---|---|
| `INTERNET` | app manifest | Every screen talks to the FastAPI backend; release builds do not get it from the debug manifest. |
| `ACCESS_FINE_LOCATION` | app manifest (geolocator) | Rider GPS (`PATCH /wallet/location`) and the customer's "use my current location" pin. While-in-use only. |
| `ACCESS_COARSE_LOCATION` | app manifest (geolocator) | Network-based fallback so the first fix is fast; paired with fine location. |
| `FOREGROUND_SERVICE` | app manifest (Android 9+) | Required to run *any* foreground service; used by geolocator during an active delivery. |
| `FOREGROUND_SERVICE_LOCATION` | app manifest (Android 14+) | Android 14+ requires this typed permission for a location foreground service (`foregroundServiceType="location"` on `com.baseflow.geolocator.GeolocatorLocationService`). |
| `POST_NOTIFICATIONS` | app manifest (FCM / flutter_local_notifications) | Order-status push notifications; requested at runtime on Android 13+ (the app prompts when a rider goes online / customer logs in — see `push_service.dart`). |
| `WAKE_LOCK` | firebase_messaging (transitive) | FCM message handling and the notification display path hold a short wake lock so a message is not lost mid-display. Standard FCM requirement. |
| `ACCESS_NETWORK_STATE` | firebase_messaging (transitive) | FCM checks connectivity before sending; harmless read-only permission. |
| `VIBRATE` | flutter_local_notifications (transitive) | Notification vibrate pattern. |
| `com.google.android.c2dm.permission.RECEIVE` | firebase_messaging (transitive) | FCM delivery permission; only the Google Play services process holds it. |
| `com.speedymealservices.app.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | AndroidX (transitive) | Generated by AndroidX so dynamically-registered receivers cannot be triggered by other apps. |

## Explicitly NOT present (and why that matters)

- **`ACCESS_BACKGROUND_LOCATION` — not declared.** Rider GPS during an active
  delivery is delivered by geolocator's **foreground service** with a visible
  persistent notification, which keeps working with while-in-use permission
  even with the screen off. This is the minimal-compliant approach: it avoids
  Play's *Background location* declaration form and the separate background
  review. The prominent in-app disclosure (`lib/widgets/location_disclosure.dart`)
  is still shown before the first OS prompt, because location *is* collected
  while the app is not visible (foreground service case).
  - Play form still required: **Foreground service (location)** declaration in
    Play Console → App content → App access and data → *Location*.
- **No `CAMERA`, no `READ/WRITE_EXTERNAL_STORAGE`, no
  `READ_MEDIA_IMAGES`.** The rider KYC upload uses `file_picker`, which on
  modern Android goes through the Storage Access Framework / system photo
  picker — no runtime permission, no Play media-access declaration.
- **No `RECORD_AUDIO`, no contacts, no phone/SMS permissions.**

## android:exported flags (Android 12+ requirement)

All 4 `android:exported="true"` components carry an explicit `intent-filter`
or are declared explicitly; all 13 `exported="false"` components (geolocator
service, FCM services/receivers, AndroidX receivers) cannot be invoked
cross-app. `MainActivity` is `exported="true"` (launcher) with
`launchMode="singleTop"` and `taskAffinity=""`.

## Play Console forms triggered by this manifest

1. **App access and data → Location → "Foreground service information"**
   required for `FOREGROUND_SERVICE_LOCATION`: declare the service type
   *Location*, when it runs (active delivery only), and point to the in-app
   disclosure.
2. **Data safety form**: precise location — collected; shared (backend);
   while-in-use + foreground-service during active delivery.
3. No background-location declaration is needed (permission absent).
